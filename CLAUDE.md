# Ploink

- Game logic lives in `server/public/shared/*-hub.js` (UMD: `require` in Node, globals `PloinkPongHub`/`PloinkBlasterHub`/`PloinkGalleryHub`/`PloinkControlHub`/`PloinkBrawlHub` in the browser). Hubs only see a minimal socket (`on('message'|'close')`, `send`, `readyState/OPEN`, `close`) so they run unchanged in Node and on the hosting phone. Never use Node-only APIs there.
- `server/public/shared/net.js` chooses the transport: WebSocket when `GET health` returns `{ploink: true}`, otherwise PeerJS/WebRTC with host election via the fixed peer id `ploink-v1-<mode>-<code>` (first one to claim it hosts). `?net=p2p` forces P2P locally, `?net=server` forces the WebSocket. Link-level heartbeats (`{"type":"__hb"}`) are filtered out before hubs/clients see them; the host's `acceptPeer` puts every guest into the host's room code.
- QR pairing existed once and was removed on purpose (user decision, 2026-11-24); don't reintroduce it without being asked.
- `sw.js` is only registered when the page is not served by the Node server; the in-app Claude browser refuses service workers, test them in Chrome against a static server.
- Ball physics run on each client; the Pong hub is only a relay. A ball's `seq` increments on every hand-off and stale `exit`/`miss` messages with an old `seq` are ignored.
- Client world coordinates: screen width = 1 unit, height = `H` (height/width). Ball `angle` is measured from straight down; on hand-off the hub mirrors `x` and `angle` (phones "face" each other).
- Blaster lanes at the top = connected, non-away opponents in hub order; hits are validated via one-time shot ids. The same code in different modes is a different room.
- Schießbude: target paths are deterministic functions of the hub clock (`targetPosition`, duplicated in `public/gallery.js`); clients sync via ping/pong and only send `shoot` for hits. Panorama x is in phone widths (seat i shows [i, i+1]), y is a fraction of screen height.
- Kontrollzentrum (`control-hub.js`): host-authoritative; panels are sent privately per player (`panel`), orders per issuer (`order`), completions are checked when the owner sends `act`. `test/control-hub.test.js` runs the hub in-process with fake sockets and shortened `CONFIG` timings (no server needed).
- Hausmeister-Trupp (`brawl-hub.js`): the hub simulates everything at `CONFIG.tickMs` and broadcasts compact `snap` arrays (state codes in `P`/`E`); `brawl.js` interpolates others ~100 ms in the past and predicts only the own walking from `PloinkBrawlHub.CONFIG`. `test/brawl-hub.test.js` manipulates hub entities directly (white-box).
- Katana-Küche (`ninja-hub.js`): like the Schießbude, fruit paths are deterministic (`fruitPosition`, shared with `ninja.js`); each phone simulates its own ninja from `CONFIG` and reports `pos`, cuts and bumps are claimed by the phone and validated by the hub (reach + last reported position). World y points up (floor = 0). Power-up effects live on the hub (`player.effects`, sent as bits in the `ninjas` rows); the own phone mirrors them in `myEffects` from `collected`/blocked messages. Shuriken: the thrower's phone simulates its own stars (`ownStars`, claims wait for the hub's star id), the hub only checks claims against the star's line (`onStarLine`).
- Katana-Küche pause: an open menu sends `pause`; the room clock (`room.now()`, Date.now() minus pauses) stands still and the phones freeze their `gameNow()` the same way, so nothing has to be shifted on resume. Pauses end after `CONFIG.maxPauseMs` or when the pausing phone disconnects.
- Full screen ends on every page change (each game is its own page): `screen-mode.js` (not `fullscreen.js`: content blockers block that file name) remembers the choice in localStorage and re-enters on the next `pointerup`; it is loaded on every page. Katana-Küche bests live per name in localStorage (`ploink-ninja-best`), the phone reports them with `best` on joining.
- Static files are served with `no-store` (browsers kept stale CSS with no-cache).
- `node --watch` inside the container does not always notice edits from the host; `docker compose restart server` when a server change does not seem to apply.
- Katana-Küche performance: `ninja.html?fps#NN` shows a frame-time meter; `window.__ninja.benchDraw(n)` times n flushed draws. The static dojo is cached in an offscreen canvas (`backdrop`, reset in `resize`), dpr is capped at 2, glows use `halo()`/`outlinedText()` instead of `shadowBlur`.
